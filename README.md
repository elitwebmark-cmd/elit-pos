# Перевірка позицій elit-web.ua по містах

Форма для співробітників у різних містах + закрита сторінка статистики. Усі відповіді пишуться в одну базу PostgreSQL.

- `/` — форма (посилання для співробітників)
- `/stats` — статистика (логін будь-який, пароль = `ADMIN_PASSWORD`)
- `/api/export.csv` — вивантаження всіх відповідей для Excel

Запити зашиті в `server.js` (масив `QUERIES`), список міст — масив `CITIES`.

## Деплой на Railway

1. Створіть репозиторій на GitHub і запуште туди цю папку:
   ```bash
   git init && git add . && git commit -m "init"
   git branch -M main
   git remote add origin git@github.com:<you>/elit-positions.git
   git push -u origin main
   ```
2. Railway → **New Project → Deploy from GitHub repo** → оберіть репозиторій.
3. У проєкті натисніть **+ Create → Database → PostgreSQL**.
4. Відкрийте сервіс застосунку → **Variables** і додайте:
   - `DATABASE_URL` = `${{Postgres.DATABASE_URL}}` (посилання на змінну бази)
   - `ADMIN_PASSWORD` = ваш пароль для статистики
5. **Settings → Networking → Generate Domain** — отримаєте адресу на кшталт `elit-positions.up.railway.app`.

Таблиці створюються автоматично при першому запуску.

## Локальний запуск

```bash
npm install
DATABASE_URL=postgres://user:pass@localhost:5432/elit ADMIN_PASSWORD=secret npm start
```

## Прогони (повторні кола перевірки)

Прогін — одне коло перевірки. Керуються на сторінці `/admin` (той самий пароль, що й для статистики).

- Форма для співробітників завжди за одним посиланням (`/`) і пише у **відкритий** прогін. Одночасно відкритий лише один.
- Якщо відкритого прогону немає, форма показує «Зараз перевірка не проводиться».
- Новий прогін: `/admin` → «Новий прогін». Запити підставляються з останнього, їх можна змінити. Галочка «Одразу відкрити» закриває поточний прогін.
- Запити прогону можна редагувати, поки в ньому немає відповідей. Потім — лише новим прогоном, щоб не зламати історію.
- Якщо співробітник відкрив форму до старту нового прогону і надсилає її після, сервер попросить оновити сторінку.
- Ім'я та місто форма пам'ятає на пристрої між прогонами.

Під час першого запуску ця версія автоматично переносить усі наявні відповіді в «Прогін 1» і залишає його відкритим.

## Як рахується статистика

- У статистиці (`/stats`) обирається прогін і прогін для порівняння (за замовчуванням — попередній).
- Стрілки ↑/↓ показують зміну позиції проти прогону порівняння (↑ — покращення). «нове» — минулого разу сайту не було в ТОП‑30, «випав» — був, а тепер немає.
- Зміни в KPI рахуються лише по містах і запитах, що є в обох прогонах.
- Графік «Динаміка по прогонах» показує середню позицію, частку в ТОП‑10 або частку знайдених у ТОП‑30 — по всіх запитах або по одному.
- Кожне місто важить однаково: якщо з міста перевіряли двоє, береться середнє по них.
- Якщо одна людина надіслала форму кілька разів у межах прогону, береться її останній запис (або середнє — перемикач на сторінці).
- «Немає в ТОП‑30» не входить у середню позицію, але враховується в частках.
- Відповідь можна виправити (ім'я, місто) або видалити: «Відповіді прогону» → «Деталі».
